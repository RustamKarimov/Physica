# Phase 12 — Thermal, gases and thermodynamics

Status: implementation specification

## Scope

Phase 12 validates Cambridge 9702 Topics 14–16 through curriculum-independent
thermal domain models, deterministic examples, registered Library content and a
no-code desktop workbench. The phase owns temperature, ideal gases, the
two-dimensional hard-particle teaching gas, Brownian motion, thermodynamic
process paths and P–V work.

This phase does not implement oscillations, heat-engine efficiency as a complete
machine model, or production export. Cycle and heat-engine content is an
explicitly labelled extension built from the same state and path contracts.

## Authority and boundaries

- @physica/physics-thermal owns scientific state, equations, observables,
  validation, scenarios and the thermal Library catalog.
- @physica/solver-particles remains the numerical authority for hard-disk
  collision evolution. The thermal package prepares deterministic initial
  states and derives teaching observables.
- SI values are authoritative: kelvin, pascal, cubic metre, joule, mole,
  kilogram and second. Celsius is an interface conversion only.
- The desktop consumes immutable scenario output and must not independently
  recalculate physics.
- Renderer output is a representation of model state. Particle drawings,
  histograms, arrows, gauges and shaded graph areas are not model authority.
- No arbitrary code, network service or AI dependency participates in model
  evaluation.

## Scientific contracts

### Temperature

- Celsius and kelvin conversion uses T/K = theta/degree-Celsius + 273.15.
- Kelvin inputs must be finite and non-negative.
- A two-fixed-point linear thermometric-property calibration maps the ice and
  steam properties to 0 and 100 degrees Celsius.
- Two-body thermal contact conserves total thermal energy for positive heat
  capacities and approaches the shared equilibrium temperature exponentially.

### Ideal gas and particles

- The analytical model enforces pV = nRT with positive absolute temperature,
  volume and amount.
- Mean translational kinetic energy per particle is 3kT/2.
- The teaching gas is a disclosed 2D hard-disk representation, not a molecular
  scale reproduction. Its elastic solver must conserve kinetic energy and
  momentum within documented floating-point tolerances.
- Initial ensembles are generated by an owned deterministic PRNG from an
  explicit integer seed and use non-overlapping grid placement.
- Temperature changes scale velocities by the square root of the absolute
  temperature ratio.
- A Brownian tracer is a larger, heavier particle within the same deterministic
  collision world. Its path demonstrates stochastic-looking motion without
  nondeterministic execution.
- Speed histograms and wall collision rate are derived observables.

### Thermodynamics

- The sign convention is delta U = Q - W_by, where positive Q enters the
  system and positive W_by is work done by the gas on the surroundings.
- Path work is the signed integral of pressure with respect to volume.
- Constant-volume, constant-pressure and ideal-gas isothermal paths are exact
  analytical segments. Piecewise-linear and closed-cycle extensions use a
  deterministic trapezoidal integral.
- Every path reports endpoints, sampled points, work, heat, internal-energy
  change, process disclosure and area-shading data from one authoritative
  result.
- Monatomic ideal-gas internal energy is 3nRT/2 where that assumption is used.

## Public model surface

The package exposes:

- temperature scale conversion, thermometric calibration and thermal-contact
  evaluation;
- validated ideal-gas state solving and kinetic observables;
- deterministic hard-particle and Brownian teaching simulations;
- thermodynamic state, path and first-law evaluation;
- PhysicalModelContract adapters for thermal contact and analytical gas state;
- immutable mandatory scenarios;
- a complete metadata-driven Physics Library registrar.

All public functions return typed, teacher-readable validation issues for
invalid inputs. Model adapters expose provenance, assumptions, validity
conditions, solver policy, state channels and observable identifiers.

## Desktop acceptance workflow

The Thermal/Gases Alpha is the default launcher view at phase completion. A
teacher can switch among temperature, gas-law, particles, Brownian, first-law
and P–V workflows; adjust native labelled controls; and observe synchronized
apparatus, equations, numerical readouts and graphs. Particle motion must honor
reduced-motion preferences and all state distinctions must be conveyed by text
or shape as well as color.

The Author workspace receives thermal templates and the registered thermal
Library. Existing alphas remain directly reachable.

## Verification gates

- reference and invalid-input tests for Topics 14–16;
- Celsius/kelvin and calibration round trips;
- thermal-equilibrium convergence and energy conservation;
- ideal-gas identity and kinetic-temperature relation;
- deterministic replay, checkpoint restore, momentum and energy tests for the
  hard-particle teaching gas;
- Brownian replay and bounded-state tests;
- first-law identity and analytical/numerical P–V area consistency;
- Library completeness and registration tests;
- exact Gallery reconciliation and accessibility tests;
- desktop shared-state, keyboard and reduced-motion smoke tests;
- repository formatting, architecture, strict TypeScript, full tests, all
  application builds and launcher preflight.

No curriculum topic is marked VALIDATED from package names alone. Topic 14, 15
or 16 may change state only when its capability, Library, Gallery, scientific
test and desktop release-gate evidence is explicit.
